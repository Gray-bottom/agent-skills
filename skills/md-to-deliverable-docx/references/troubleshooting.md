# 排查手册

`md-to-deliverable-docx` 遇到异常时读这份。SKILL.md 只列常见现象，这里放细节、核对方法和覆盖边界。

## 公式

**症状**：正文里出现 `\frac`、`\sum`、`$$` 这类原始 TeX；或者行内公式的上下标塌成了普通字符。

**原因**：走了两段式 md→html→docx。

**核对方法**：解开 docx（docx 就是 zip），读 `word/document.xml`，搜 `<m:oMath`。数量为 0 说明公式没有转成 Word 原生公式。

**修法**：改直连重新导出。

**覆盖边界**，实测于 pandoc 3.10 可以正常转成原生公式的写法：

- 行内 `$...$`、行间 `$$...$$`
- `\frac`、`\sum`、上下标
- `\begin{cases}` 分段函数
- `\begin{aligned}` 多行对齐

没有验证过的写法：

- `\ce{}`、`\SI{}` 这类化学与单位宏
- 使用者自定义的 `\newcommand` 宏
- 公式里嵌 `\begin{tabular}`

遇到没验证过的宏，导出之后人工看一遍，不要假定成功。

## 上下标

**症状**：`H<sub>2</sub>O` 变成 `H2O`，或者 `<sub>` 标签本身留在正文里。

**修法**：改写为原生语法 `H~2~O` 与 `x^2^`。这两种写法在直连与两段式下都正常。

## 图片与题注

- `![alt](path "title")` 里的 title 会成为题注，alt 不会。
- 走中文路径中转流程时，相对路径会断链，处理办法见 SKILL.md 的「中文路径与图片」。
- 题注编号由 pandoc 顺序生成，与 Word 的题注交叉引用不是一套机制。需要自动编号或交叉引用的文档要人工补。

## 表格

- 三线表依赖参考模板里的 `Table` 样式。模板没设这个样式时，输出的是普通四边框表。
- 核对方式：`word/document.xml` 里表格应带 `w:tblStyle` 指向 `Table`、`tblLook` 含 `firstRow="1"`、首行含 `<w:tblHeader/>`。三条齐备，表头下面那条 0.5pt 线才画得出来。

## 字体

- 字体、字号、行距全部由参考模板决定，命令行不覆盖。
- 模板只设了西文字体时，中文会回退到 Word 的默认中文字体，可能出现中英字重不协调，极端情况显示为方块。核对方式是打开成品看，或在模板里补上中文字体设置。

## 使用者要求核对 docx 结构时

平时不做这件事，只有使用者明确要求才做。三个容易误判的点：

- 模板自带的 heading 样式 id 是数字，形如 `10`、`20`、`3`，不是 `Heading1`。按名字统计标题数会得到 0，不要据此断定标题样式丢了。
- 加粗标签在 XML 里写作 `<w:b />`，`b` 和 `/` 之间有一个空格。用 `<w:b/>` 去匹配会误判成完全没有加粗。
- 抽查关键串在不在，并检查有没有替换字符 `\ufffd`，那是乱码的标志。

## 环境限制

- 本机没有 LibreOffice 与 pdftoppm，生成不了 PDF 预览或成品截图，不要承诺提供。
- 转换只是把 Markdown 映射成 Word 结构，不校验排版是否达到出版标准。成品要使用者自己打开核对。
